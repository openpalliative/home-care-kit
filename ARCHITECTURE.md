# home-care-kit: архитектура

Срез 11.10.2026. Поверх `../PLATFORM.md` (техника), `../UX_MAP.md` (адреса, тексты, состояния) и `../PLAN.md` (D1-D10). Если здесь что-то расходится с ними, правы они, а расхождение записывается в `../STATUS.md`. Основа идей: итоговый разбор идей проекта, карточки 1, 4, 6, 7, 9.

Название для людей: **Листы для дома**. Префикс `hc`, порт 8704, PWA, адрес на Pages `/home-care-kit/`.

## 0. Решения синтеза

Свели две позиции архитекторов («от людей» и «от данных») и критику. Что выбрали и почему:

| # | Вопрос | Решение |
|---|---|---|
| S1 | Адреса | По UX_MAP: `night/`, `emergency/`, `discharge/`, `conclusion/`, `ahead/`, служебные `data/` и `saved/`. Короткие, их диктуют и печатают |
| S2 | «Блокировка печати» после срока | Полностью запретить печать браузер не даёт (Ctrl+P), а отказ ночью хуже листа с пометкой. Поэтому: наша кнопка печати заменяется кнопкой «Проверить и продлить», превью получает надпись «Не действителен». Если человек всё равно печатает через меню браузера, `@media print` ставит на лист крупное «Не действителен с ДД.ММ.ГГГГ, номера не проверены» и прячет блоки с данными соседей. Пустой бланк печатается всегда |
| S3 | Номера из данных на листе | Fail closed (PLATFORM 4.3). На лист попадает только номер с `verified:true`. Непроверенный номер (линия по обезболиванию из `region-lines`, горячая линия из `now.yaml`) виден на экране со статусом «Не проверено» и кнопкой «Я позвонил, номер работает: вписать». После этого он становится значением семьи с датой подтверждения и печатается как её собственный номер. Добавочный (`ext` в `region-view`) переносится вместе с номером. Если в снимке pal-directory номеров нет (режим `links`), вместо подсказки ссылка на карточку региона в pal-directory. Так сделано в `templates/partials/sheet.html.j2` (кнопка `data-hc-confirm`) и `assets/js/hc-night.js` |
| S4 | Откуда 103, 112 и горячая линия | Только `opsite/now.yaml` хаба (`opdata.now`, приходит с `sync-ui`). Своего `phones.yaml` нет |
| S5 | Срок годности | Считается сам из даты проверки семьёй и проверенных лет календаря (раздел 2.4). Без ручного декабрьского релиза |
| S6 | «103 обязана обезболить» | Утверждение и сценарий разведены. Сценарий «что сказать диспетчеру» - наш текст с плашкой `medical`, печатается. Утверждение про обязанность - отдельный блок `quote` с цитатой п. 11 (норма `388n`). Цитаты нет на портале, поэтому блок `verified:false` и на лист не попадает |
| S7 | `conclusion/` и `discharge/` | Статичные справочные страницы, работают без JS. JS только переключает ветку и группу. Ничего не хранят |
| S8 | Хранение | `night`: хранить. `emergency`: спросить на первом шаге («Это ваше устройство?»), до ответа ничего не пишем. `discharge`, `conclusion`, `ahead`: не хранить. Группа заболевания никогда не попадает в URL и хранилище |
| S9 | Автоматизация | Потребитель снимков: в сеть сам не ходит, в `main` сам не коммитит, обновления только PR. Чтобы GitHub не выключил расписание, в конце `sync-data.yml` вызов `enable` для самого workflow (раздел 5) |
| S10 | Связь с соседями | `pipeline/export.py` строит из `vendor/` три внутренних датасета (`norm-view`, `region-view`, `holiday-runs`). Сайт читает только их. Если сосед поменяет поля, правится один адаптер, а не шаблоны |
| S11 | `lib/deadlines.js` | В MVP не берём: праздничный калькулятор по сроку рецепта отложен, пока не найден пункт о сроке бланка. Нужен только календарь |
| S12 | PNG и пересылка | PNG позже. У экстренного листа нет `<op-share>` в мессенджеры, только «Скопировать текст» для медкарты в телефоне |
| S13 | QR | Предел 400 байт, уровень M, UTF-8 в байтовом режиме. Библиотека грузится только на `emergency/` динамическим `import()` |
| S14 | Мифы о паллиативной помощи на `conclusion/` | Позже. В MVP никаких «подходит / не подходит», все пункты группы показаны одинаково |

## 1. Что строим

### 1.1 MVP (один прогон)

- 7 страниц: корень, 5 листов, `data/`, `saved/`
- Лист **«Карта на ночь и праздники»** (`night/`): 2 стороны A4, мастер из 3 шагов, сохранение на устройстве, срок годности, подсказки номеров региона, ближайшие длинные выходные из календаря
- **«Лист для скорой»** (`emergency/`): детский профиль на 18 полей, A4 и карточка в кошелёк (A6 на листе A4 с линией реза), QR с данными внутри кода, водяной знак «Не проверено» после 90 дней, копирование текста для медкарты
- **«До того, как забрать домой»** (`discharge/`): развилка «заключение есть / нет / не знаю», чек-лист с пустыми квадратами для ручки
- **«Что даёт заключение о паллиативной помощи»** (`conclusion/`): выбор группы (только в памяти страницы), дословные показания из `pal-norms` или честное «текст ещё сверяется» со ссылкой на страницу официальной публикации, «что не придёт само»
- **«Что подписать, пока человек может»** (`ahead/`): дерево из 6 вопросов, лист «что оформить на этой неделе»; все ветки с плашкой «черновик для юриста»
- Без JS: все страницы читаются, каждый лист печатается пустым бланком для ручки, дерево и все группы раскрыты списком
- PWA: офлайн после первого визита, плашка «Вышла новая версия. Обновить»
- Демо `?demo=1` на `night/` и `emergency/`: выдуманные значения, ничего не сохраняется, вверху «Пример на выдуманных данных»
- Экспорт, импорт и удаление своих записей на `saved/`
- Плашки черновика по листам: `night` both, `emergency` medical, `discharge` both, `conclusion` both, `ahead` legal
- Тексты «Последние дни» и «Смерть дома: кого звать и нужна ли полиция» на сайте не показываются даже заглушкой, они в «позже» (нужен текст медика и юриста в РФ)

### 1.2 Позже (не в этом прогоне)

- PNG листа для пересылки
- Праздничный `.ics` по дате рецепта (после того как найден пункт о сроке бланка рецепта)
- Карточка у аппарата, взрослый профиль экстренного листа, лист для сиделки, «боль для врача»
- Мифы на `conclusion/`, региональный слой показаний
- `pipeline/impact.py`: список затронутых листов в теле PR синхронизации
- Перевод руководств IHI 2021 для `ahead/`
- Тексты «последние дни» и «без полиции» после подписи юриста и медика в РФ
- Typst

### 2.2 Первый экран телефона (360×640, размер A)

- **Корень:** шапка в две строки; H1 «Листы для дома»; одна строка пояснения; первая карточка «Карта на ночь и праздники» с отметками «2 листа A4», «5 минут», «Работает без интернета» и ссылкой-заголовком
- **Лист с мастером** (`night/`, `emergency/`): H1; компактная плашка черновика под H1 (заголовок и одна строка, полный текст в `<details>`, страницы задают плашку сами, `draft_default: none` в `site.yaml`); ссылка «Распечатать пустой бланк» (`data-hc-blank`); «Шаг 1 из 3. Заполнить»; первое поле без прокрутки. После шага 1 кнопка «Дальше» закреплена внизу экрана, на шаге 3 там же «Распечатать или сохранить PDF»
- **Первый вход на `emergency/` и `night/`:** вместо первого поля вопрос «Это ваше устройство?» двумя кнопками: «Да, сохранять здесь» и «Нет, не сохранять», и ссылка «Распечатать пустой бланк». Ответ общий для обоих листов: `localStorage['hc:device-save']` (`assets/js/hc-device.js`; старый ключ `hc:emergency-save` читается и убирается). С `?demo=1` вопрос не задаётся и ничего не сохраняется
- **`discharge/`, `conclusion/`, `ahead/`:** H1, плашка черновика, первый вопрос или радио развилки

На ширине от 960px: форма слева, превью листа справа (масштаб под колонку, `aria-hidden="true"`). На телефоне превью показывается на шаге «Проверить».

### 2.3 Мастер листа

Шаги одинаковые: «Заполнить», «Проверить», «Распечатать или сохранить PDF» (`op-steps`).

- **Заполнить.** Поля `op-field`, `label` над полем, подсказка «зачем». Даты допускаются и полем `type=date`, и текстом `ДД.ММ.ГГГГ` (старые iOS). Ограничение длины видно счётчиком «осталось 20 знаков». Пустое поле на листе печатается линией для ручки
- **Проверить.** Превью целиком. Для `night/` список всех номеров с галочкой «Проверил звонком или по документам» и кнопкой «Номера проверены»: она ставит `checked_at = сегодня` и показывает «Данные верны до ДД.ММ.ГГГГ». Для `emergency/` поля «Кто проверил» и «Дата проверки»
- **Распечатать.** `<op-print>`. Для `night/` подсказка «Две стороны одного листа или два листа». Для `emergency/` переключатель «Лист A4» / «Карточка в кошелёк» (класс на `<body>` до `print()`) и подсказка «Отключите колонтитулы в настройках печати»
- `<title>` всех листов постоянный («Лист для скорой - Листы для дома»), без имени и группы: браузер пишет его в колонтитул и имя PDF
- Живые подсказки: `aria-live="polite"` только у строки «Сохранено» и у ошибок

### 2.4 Срок годности

Чистая функция `lib/validity.js`:

```
validUntil({ checkedAt, recheckDays = 183, verifiedYears, lineDates = [], lineDays = 365 })
  = min(
      checkedAt + recheckDays,
      31.12 последнего года из verifiedYears (если лет нет: 31.12 года checkedAt),
      для каждого номера из region-view, напечатанного как verified: его verified_at + lineDays
    )
isExpired(validUntil, today) = today > validUntil
needsWatermark(checkedAt, today, days = 90) = checkedAt пуст или today > checkedAt + days
```

- `verifiedYears` берутся из `holiday-runs` (элементы `kind: year`, `verified: true`). Новое постановление о переносах выходит в сентябре: `pal-norms` его заносит, наша синхронизация приносит, и срок листов, проверенных после этого, сам доходит до 31.12 следующего года
- `night/` с истёкшим сроком: статус «Срок» и текст UX_MAP «Срок годности листа истёк [дата]. Обновите страницу и проверьте номера, потом распечатайте заново»; печать по S2
- `emergency/` не истекает, но после 90 дней с даты проверки на листе водяной знак «Не проверено» и рамка `stale`
- Без JS срок не считается: на бланке строки «Проверено: ____» и «Данные верны до: ____» для ручки

Подвал каждого листа (`sheet_footer`): «Данные от ДД.ММ.ГГГГ, сверьте до ДД.ММ.ГГГГ», версия листа, адрес страницы текстом, текст черновика.

### 2.6 Переходы (UX_MAP 4.3)

- Принимаем во фрагменте: `region` (на `night/`, сверка с `region-view`), `back` (везде). Остальное отбрасываем и убираем фрагмент
- Отдаём: `night/` -> pd `regions/<iso>/` «Откуда номер»; `emergency/` -> `night/`; `conclusion/` -> pn `indications/` «Показания дословно» и ok `case/#new=1&s=oral-refusal&back=conclusion`; `discharge/` -> ok `scenarios/discharge/`, dv `` «Кто выдаёт изделия», `conclusion/`
- Ссылки только через `xurl()`. Пока в платформе нет `xparams.js`, локальная копия `assets/js/hc-xparams.js` и строка в STATUS «В платформу»

## 3. Данные

### 3.1 Принцип

home-care-kit сам ничего снаружи не скачивает и не парсит. Свои данные - тексты и поля листов, их пишут люди. Нормы, календарь и номера приходят готовыми снимками `openpalliative-dataset/1` от `pal-norms` и `pal-directory`, номера 103, 112 и горячей линии из `now.yaml` хаба. Смена формата первоисточника ломает наблюдателя соседа, а не листы.

- **блок**: `id`, `kind` (text, locked, script, fields, numbers, holidays, checklist, quote, indications, not-automatic, placeholder, qr, outcomes), `title`, `text`, `lines[]` (подстановки `{field_id}`), `items[]`, `field_ids[]`, `now_ids[]`, `region_roles[]`, `groups[]`, `norm_ids[]`, `quote_refs[]`, `links[]` (`label`, `repo`, `path`, `params`), `screen`, `print`, `verified`, `verified_at`, `source_ref`, `review`
- **пункт** (в checklist и not-automatic): `id`, `text`, `detail`, `who`, `when`, `branch`, `norm_ids`, `quote_refs`, `links`, `verified`, `verified_at`, `source_ref`, `review`
- **дерево**: `start`, `questions[]` (3-7; `id`, `text`, `help`, `options[]` с `value`, `label`, `next` и/или `outcomes[]`), `outcomes[]` (`id`, `title`, `what`, `take[]`, `always`, `norm_ids`, `quote_refs`, `links`, `verified`, `verified_at`, `review`)

Правила правдивости для текстов листов (их ловит pytest):

- слово «положено» запрещено; «обязан», «имеете право», «должны» допустимы только у пункта с `norm_ids` и `quote_refs`
- формулировки просьбой: «попросите», «спросите»
- без доз, единиц, названий из `opsite/lint/drugs.txt`, без порогов и диапазонов показателей (ПП 1684). В подсказке поля `usual_values` прямо: «Перепишите из выписки. Мы не подсказываем значения»
- у поля `pain_relief` нет автодополнения, списков и единиц
- номер акта литералом в тексте не пишем, только `norm_ids`

### 3.5 Как читается

- YAML через `opsite.data.read_yaml` (BaseLoader) и `coerce` по схеме. `coerce` не ходит по `$ref`, поэтому `pipeline/export.py` сначала разворачивает `$defs` в схеме (`inline_refs`, 15 строк) и только потом приводит типы. Строка в STATUS «В платформу»: научить `coerce` `$ref`
- `export.datasets(root)` отдаёт 5 конвертов через `opsite.data.make_envelope`: `sheets`, `entrypoints` (публичные), `norm-view`, `region-view`, `holiday-runs` (внутренние)
- внутренние строятся из `vendor/pal-norms/v1/{acts,calendar,indications}.json` и `vendor/pal-directory/v1/{regions,region-lines}.json` функциями `pipeline/views.py`. Если снимка нет, датасет пустой, а все зависящие блоки уходят в «не проверено». Сборка не падает
- `HC_FIXTURES=1` подменяет внутренние датасеты фикстурами из `tests/fixtures/` (только для разработки сайта; сборка ставит на все страницы плашку «Пример на выдуманных данных»; `gate.sh` с этой переменной падает)

### 3.6 Правила проверки

- `printable` в `norm-view` вычисляет адаптер: акт `in_force` и `verified:true`; цитата с непустым `text_verbatim`, `verified:true` и, для сканов, `ocr_verified:true`; иначе `printable:false` и `reason` по-русски
- `printable` в `region-view`: `verified:true`, `verified_at` не старше `line_days`, регион не исключён
- исключённые территории (6 субъектов) в `region-view` не попадают: адаптер фильтрует по `opsite/lint/territories.yaml`, pytest проверяет и фикстуры
- у каждого блока и пункта `verified`, `verified_at`, `review`; лист с непустым `review.needs` и `reviewed_by: null` показывает плашку черновика

### 4.2 Берём (`deps.yaml`)

```yaml
pal-norms:
  major: 1
  datasets: [acts, calendar, indications]
pal-directory:
  major: 1
  datasets: [regions, region-lines]
```

Минимум полей, которые читает адаптер (заявка соседям, строка в STATUS):

- `acts`: `id`, `title` (короткое название), `status`, `eoNumber`, `url`, `verified`, `verified_at`, `in_force_from`. Записи: `1094n`, `505n`, `208n-243n`, `398n`, `388n` (`unknown` или `verified:false`), `424n` (`not_yet_in_force`), `gk-185`, `gk-185-1`, `gk-188`, `gk-1174`, `323-fz`, `pgg-2026`
- цитаты (в `acts` или отдельным датасетом, решает pal-norms): `id` вида `<norm_id>-p<N>`, `norm_id`, `point`, `quote_verbatim`, `page`, `ocr_verified`, `verified`. Ждём: `388n-p11`, `1094n-p3`, `208n-243n-p13`, `208n-243n-p17`, `208n-243n-p20`, `gk-188-p1`, `gk-1174-p3`
- `calendar`: по году `year`, `verified`, `source_ref` на ПП с eoNumber; по дню признак нерабочего дня. Адаптер сам собирает подряд идущие нерабочие дни в периоды от 3 дней
- `indications`: `group` (general, dementia, stroke, als, chf), `point`, `quote_verbatim`, `eoNumber`, `pdf_page`, `ocr_verified`, `verified`
- `regions`: `id` (ISO), `name`
- `region-lines`: `id`, `region_id`, `role` (ждём роль линии по обезболиванию), `label`, `phone`, `hours`, `is_24x7`, `other_org`, `verified`, `verified_at`, `source_ref`

Пока соседи не собраны, работаем на фикстурах. Если сосед назвал поле иначе, правится `pipeline/views.py` и его тест, сайт не трогаем.

## 5. Автоматизация (только файлы, ничего не запускаем)

У каждого workflow `permissions: {}` наверху и свои права у job, `timeout-minutes`, `persist-credentials: false` у checkout, действия закреплены по SHA с тегом в комментарии. Сборка везде с `OP_TARGET: pages` на уровне job, как на Pages

| Файл | Когда | Что делает | Права |
|---|---|---|---|
| `.github/workflows/checks.yml` | PR, push в `main`, вручную | job `actionlint` (`scripts/actionlint`: actionlint 1.7.12 и shellcheck 0.10.0 с sha256 из `scripts/tools/install`); job `gate`: pytest, `pipeline.audit` без `--open-issues`, сборка и `opsite check --ci`, `scripts/indications_gate.py`, unit, e2e (браузеры задаёт `playwright.config.js`, в CI поставлены chromium, firefox и webkit), скриншоты, потом сборка и e2e на фикстурах (`HC_FIXTURES=1`, без `OP_TARGET`, чтобы проверить и путь с открытыми показаниями). Concurrency по номеру PR, на PR старый прогон отменяется | `contents: read` |
| `.github/workflows/pages.yml` | push в `main`, вручную | сборка, `check --ci`, сторож показаний, проверка `base: /<repo>/` и наличия `index.html`, `404.html`, `sitemap.xml`, `data/v1/index.json`, деплой на Pages | build `contents: read`, deploy `pages: write, id-token: write` |
| `.github/workflows/release.yml` | тег `v*` | pytest, сборка как Pages, сторож показаний, `<repo>-<тег>-site.zip`, отдельно `<repo>-<тег>-data.zip` с `_site/data/v1`, `SHA256SUMS`, `gh release create --verify-tag`. Тег и имя репо только через `env` | `contents: write` |
| `.github/workflows/sync-data.yml` | `cron: "43 5 * * 2"`, вручную | см. ниже | `contents: write, pull-requests: write, issues: write, actions: write` |

`sync-data.yml` по шагам:

1. установка (`checkout`, `setup-uv` без кэша, `uv sync --frozen`)
2. `scripts/sync-report pages`: `opsite sync-data --from pages`, тело PR и метка (`review:legal`, если поменялся `vendor/pal-norms`, иначе `review:data`)
3. `pytest`, сборка, `opsite check --ci`, сторож показаний. Если что-то упало, pull request всё равно открывается с припиской в теле, а запуск в конце красный
4. если в `vendor/` или `deps.yaml` есть разница: `peter-evans/create-pull-request`, ветка `sync/<дата>`
5. pull request от бота сам проверки не запускает, поэтому после создания или обновления `gh workflow run checks.yml --ref sync/<дата>`
6. `uv run python -m pipeline.audit --open-issues` пишет `_reports/audit.json` и открывает issue с меткой `audit` (дубли отсекаются по `sha256(kind+key)` в заголовке):
   - снимок соседа старше его `stale_after_days`
   - после 01.11 в `holiday-runs` нет проверенного следующего года: «Календарь на YYYY не утверждён: листы истекут 31.12»
   - 1-7 декабря: «Сверить листы на YYYY+1 и выпустить релиз»
   - `review.reviewed_at` старше 365 дней у листа с проверкой
7. последним шагом с `if: always()` `gh api -X PUT repos/$GITHUB_REPOSITORY/actions/workflows/sync-data.yml/enable`, чтобы расписание не выключилось через 60 дней без коммитов. Работает ли это как сброс счётчика, проверить после публикации (`docs/release.md`)

Само в `main` не коммитится ничего: всё, что меняется в репо, видят семьи. Как живёт без людей: листы сами считают срок годности по дате проверки семьи и проверенным годам календаря, страницы показывают дату данных, устаревшие снимки дают issue. Если никто не мержит PR, листы продолжают работать до 31.12 последнего проверенного года, потом честно показывают «Срок истёк», а пустой бланк печатается всегда.

### 6.2 Контракт между агентами

- **Агент данных** отдаёт сайту только `ctx.data[name]` пяти датасетов по схемам из `data/schema/`. Сайт никогда не читает `vendor/` и `data/*.yaml` напрямую
- **Агент сайта** берёт поля и блоки только из `ctx.data`. Любая новая потребность в данных - это поле в схеме: сайт пишет строку в STATUS («home-care-kit: сайту нужно поле X»), агент данных добавляет его в схему, фикстуру и данные
- В рантайме JS читает `data/v1/region-view.json` и `data/v1/holiday-runs.json` (только `night/`). Определения полей и порядок QR приходят из разметки (`data-hc-*`), `sheets.json` в рантайме не нужен
- Разметка для JS (внутреннее дело сайта, но закреплено для тестов): поле `data-hc-field="<id>"`, вывод в превью `data-hc-out="<id>"`, блок `data-hc-block="<id>" data-hc-print="own|data|locked"`, QR `data-hc-qr-order`, `data-hc-qr-key`; классы на `<body>`: `hc-expired`, `hc-watermark`, `hc-paper-wallet`, `hc-blank`, `hc-demo`
- Хранение: `openStore('home-care-kit')`, одна запись на лист (`key = sheet_id`), формат `hc-record/1`: `{format, sheet_id, sheet_version, values, confirmed: {field_id: дата}, checked_at, updated_at}`. Неизвестные поля при чтении сохраняются. Экспорт `hc-export/1`: `{format, exported_at, records: []}`, имя файла `listy-dlya-doma-ГГГГ-ММ-ДД.json`, перед сохранением предупреждение «Файл не зашифрован. Храните его как медицинские документы»
- `localStorage`: только общие ключи платформы `op:prefs` и `op:region` и свои `hc:*` (`hc:device-save`). Удаление на `saved/` стирает базу `op-home-care-kit` и все ключи `hc:*`

Сигнатуры `lib/`:

```js
validUntil({ checkedAt, recheckDays, verifiedYears, lineDates, lineDays }) // -> "YYYY-MM-DD"
isExpired(validUntil, today)                // -> boolean
needsWatermark(checkedAt, today, days)      // -> boolean
buildPayload(fields, values, { limit: 400 })
  // -> { text, bytes, included: [id], omitted: [{ id, reason }] }
  // строки "qr_key: значение" по qr_order, даты ДД.ММ.ГГГГ, переносы в "; ", значения со ссылками выкидываются
walk(tree, answers)    // -> { next: question_id | null, outcomes: [id] }  исход always добавляется всегда
allPaths(tree)         // -> [[answer...]] для тестов
upcomingRuns(runs, today, horizonDays = 120) // -> [{ from, to, days }]
inRun(date, runs)      // -> boolean
normalizeRecord(raw)   // -> hc-record/1
```

QR (`assets/js/hc-qr.js`): `const { default: qrcode } = await import("../vendor/qrcode-generator/qrcode.js")`, перед `addData` подменить `qrcode.stringToBytes = s => Array.from(new TextEncoder().encode(s))` (по умолчанию библиотека режет символы до байта), уровень `M`, `typeNumber 0`, вывод `createSvgTag` с полями 4 модуля. Если `bytes > 400`, в код идут первые поля по `qr_order`, а под превью «В код вошли не все поля: ...». Размер кода: 60 мм на A4, 50 мм на карточке. На шаге 3 галочка «Добавить код на лист», по умолчанию включена. Подпись «Код читается любой камерой телефона. Внутри только текст с этого листа». Бюджет 60 КБ на JS страницы `emergency/` превышается только динамической загрузкой библиотеки: исключение записано здесь, строка в STATUS для `opsite check`.

## 8. Риски

1. **Неверный номер ночью хуже пустого листа.** Fail closed для номеров из данных, подтверждение семьёй, срок годности, `line_days`, issue про календарь
2. **Нет официального текста 388н п. 11.** Утверждение про обязанность скорой не печатается. Сценарий «звоните 103, скажите диспетчеру» печатается как наш текст с плашкой `medical`. Слово «обязана» появится только с цитатой из ИПС, сверенной мейнтейнером в РФ
3. **424н с 01.01.2027 меняет порядок скорой.** Должен быть в `acts` у pal-norms как `not_yet_in_force`; до полного OCR не считаем, что п. 11 не тронут
4. **Прил. 1 к 208н/243н только сканом.** До `ocr_verified` лист «что даёт заключение» показывает ссылку на страницу публикации, а не цитату
5. **Номера регионов.** Публиковать ли xlsx РЗН на Pages до двух мейнтейнеров в РФ, решает Кирилл. Пока поле линии по обезболиванию остаётся ручным
6. **Safari стирает IndexedDB через 7 дней без визитов.** Главное хранилище - бумага и файл, это написано на `saved/` и на шаге 3
7. **Плотный QR.** Предел 400 байт, проверка декодом в e2e и камерами iOS и Android вручную у мейнтейнера
8. **Чувствительные данные экстренного листа.** Вопрос про устройство, без пересылки в мессенджеры, экспорт с предупреждением, CSP платформы, все инструменты на одном origin (отдельная база `op-home-care-kit`, CODEOWNERS на `assets/js` во всех репо)
9. **ПП 1684.** Поля без подсказок значений, без автодополнения препаратов, пожелания с подписью, lint по `drugs.txt`
10. **Листы умирают без мейнтейнера.** Это честно: после 31.12 последнего проверенного года карта на ночь показывает «Срок истёк», пустой бланк работает всегда
